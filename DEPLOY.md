# Бесплатная демонстрация на GitHub Pages — редакция v4.0

**Платный хостинг не нужен для работы нового подбора.** Публичные файлы (`index.html`, `enhancements.css`, `enhancements.js`, `vehicle-data.js`, `price-data.js`, `assets/`, `data/`) публикуются обычным GitHub Pages. На сайте сначала видны 30 популярных марок; кнопка раскрывает все 99. После выбора модели и поколения появляются четыре карточки услуг с кнопкой записи. Поиск предусмотрен только для марки. **Никаких заявок, клиентов, заказов или отзывов в базу GitHub Pages не сохраняет.** Для связи используется форма, которая готовит письмо с выбранной услугой и контактами, и телефон. На GitHub Pages заявление НЕ отправляется автоматически: посетитель должен самостоятельно отправить письмо из почтового приложения.

## Публикация без сервера (Windows)

1. Распакуйте архив в папку `AvtoReyka46`; в ней должны быть `index.html`, `publish.ps1`, `assets/logos` и прочие файлы.
2. Установите **Git** и **GitHub CLI** (`gh`). Выполните `gh auth login` и войдите в аккаунт с правами на репозиторий `zoshevjoker/avtoreyka46-site`.
3. В PowerShell в папке проекта запустите `./publish.ps1` (на Windows: `.\publish.ps1`). Скрипт безопасно клонирует существующую ветку `main` во временную папку, настраивает локальную для этого коммита Git-идентичность из авторизованного аккаунта GitHub (не изменяя глобальную конфигурацию) и копирует только статические файлы. Он не удаляет другой контент репозитория и не делает принудительных публикаций (`--force`).
4. После успешного push откройте https://zoshevjoker.github.io/avtoreyka46-site/#home и обновите страницу с очисткой кеша (**Ctrl+F5**).
5. Если GitHub Pages настроен на другую ветку или папку, поменяйте эту настройку в GitHub → Settings → Pages либо адаптируйте скрипт — не создавайте параллельный репозиторий.

### Как редактировать марки и модели

Данные хранятся в `data/vehicles.json` (редактируемый источник) и встроенном для offline-работы файле `vehicle-data.js`. После правки JSON пересоберите `vehicle-data.js` командой из папки `AvtoReyka46`:

```bash
python build_static_data.py
```

Скрипт проверит идентификаторы и ссылки моделей/поколений и выпустит JavaScript для GitHub Pages. Каждый объект `brands` имеет `id,name`, `models` — `id,brand_id,name`, `generations` — `id,model_id,label,year_from,year_to`. `brand_logos` содержит пути к 99 локальным изображениям в `assets/logos`: 9 исходных логотипов плюс 90 миниатюр, подготовленных из предоставленного скриншота. Миниатюры имеют ограниченное исходное разрешение; для производственной публикации рекомендуется заменить их на официальные разрешённые SVG/PNG. При замене можно оставить прежние имена файлов.

### Как добавлять **подтверждённые** цены

Откройте `price-data.js`. Секция `offers` пуста до поступления прайса, утверждённого техцентром. Пример **структуры** записи (НЕ публиковать эти числа без проверки):

```javascript
// Структурный пример — значения вымышленные, только для демонстрации формата:
// {generation_id:1, service_id:'repair', confirmed:true, published:true,
//  available:true, price_from:10000, price_to:null, timeframe:'по согласованию',
//  description:'Описание работ после проверки у мастера'}
```

Поддерживаемые `service_id`: `diagnostic`, `repair`, `install`, `replacement`. Идентификатор поколения найдите в `data/vehicles.json`. Прайс **не** наследуется от другой марки или модели. Цена по поколению выводится только при `confirmed:true` и `published:true`; иначе посетитель видит общую ориентировочную карточку. Публикация/редактирование через браузерную админ-панель недоступны без сервера; для бесплатного этапа изменяйте файлы и повторно запускайте публикацию.

### Внешние примеры цен на демонстрации

Для показанного пользователем автомобиля Daihatsu Applause (A101/A111) 1989–2000 в `price-data.js` добавлены **только справочные цены другого сервиса со скриншота пользователя**: 9 600 ₽ за ремонт и 7 000 ₽ за монтаж/демонтаж. В карточках они отдельно подписаны как пример стороннего прайса **не являющийся стоимостью «АвтоРейка46»**. Поле `reference_examples` не смешивается с подтверждёнными собственными ценами `offers`. Для других поколений индивидуальные цены не придуманы. Чтобы загрузить собственный прайс, заполните `offers` только подтверждёнными компанией значениями.

### Ограничения демонстрации

- **99 марок, 372 модели и 59 записей поколений** — демонстрационный справочник для выбора, а не подтверждённый список обслуживаемых авто.
- Неизвестное поколение можно заменить введённым годом выпуска, без автоматического определения типа рейки.
- Базовые суммы по видам ремонта — ориентиры из предыдущей версии сайта, не стоимость выбранного автомобиля. Проверьте и утвердите их перед окончательной коммерческой публикацией.
- Неподтверждённые услуги, цены, сроки и совместимость **не выдаются** за окончательный расчёт.
- Для реальных онлайн-заявок, закрытого рабочего стола, отзывов по завершённым заказам и синхронизации с сотрудниками в будущем нужен сервер. В бесплатной версии эти функции не имитируются.

# АвтоРейка46 — развёртывание и изменения

## 1. Структура

Существующая HTML-страница и её фирменное оформление сохранены; дополняющие стили и скрипт вынесены отдельно. Сайт можно запускать вместе с сервером **FastAPI + SQLite**, либо публиковать публичные HTML/CSS/JS на GitHub Pages и размещать API на отдельном HTTPS-домене.

**Важное отличие от исходного архива:** прежние кабинеты, тестовый каталог, тестовые SMS и показатели из `localStorage` больше не доступны посетителям в навигации. На GitHub Pages без API выбор марки → модели → поколения работает через локальный справочник `vehicle-data.js`; при этом нет права считать сохранённые данные подтверждёнными ценами или остатками. Для заявок и подтверждённых через сайт отзывов требуется сервер; в офлайн-режиме предлагаются прямой звонок и письмо.

## 2. Локальный запуск (сайт и API на одном адресе)

Нужны Python 3.11+ и терминал в папке `AvtoReyka46`:

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
# source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python -m backend.manage create-admin --login owner
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Создайте **собственный сильный пароль** (от 14 символов) в интерактивном запросе. Пароль не записывается в исходный код. Откройте `http://127.0.0.1:8000/` и перейдите во вкладку «Вход сотрудника». База по умолчанию создаётся в `~/.avtoreyka46/ar46.sqlite3` — **вне публичной папки**. Не кладите её на GitHub Pages.

Данные не мигрируют автоматически из браузерных демо-записей: они были тестовыми и не должны считаться реальными заказами или подтверждёнными отзывами.

## 3. Публикация

### Рекомендуемо: единый сервер

На VPS установите зависимости, задайте безопасное постоянное расположение `AR46_DB_PATH` (вне раздаваемой веб-папки), запустите ASGI-приложение под менеджером процессов и поставьте Nginx/Caddy с HTTPS перед Uvicorn. Закройте прямой внешний доступ к серверному порту и настроьте регулярные резервные копии SQLite с контролем доступа. Файлы внутри `backend/` — это серверный код, его не раздавать как публичную статику. При обслуживании API одним сервером `config.js` оставьте как есть (`window.AR46_API_BASE = ''`).

### GitHub Pages + отдельный API

1. Разверните API на HTTPS-домене, например `https://api.example.org` (это **пример**, не готовый адрес).
2. В `config.js` задайте реальный адрес API: `window.AR46_API_BASE = 'https://ваш-api-домен';`.
3. Разрешите CORS только с фактического origin сайта, например переменная окружения `AR46_ALLOWED_ORIGINS='https://owner.github.io'`. Если есть несколько разрешённых сайтов, перечислите через запятую.
4. Запустите `publish.ps1` из папки проекта на Windows с установленными `git` и `gh`. Скрипт безопасно клонирует существующий репозиторий `zoshevjoker/avtoreyka46-site` и обновляет только публичные файлы `index.html`, `config.js`, `enhancements.js`, `enhancements.css`, `vehicle-data.js`, `assets/rack-display.jpg` и документацию. Серверный код, SQLite и тесты **не** публикуются. FastAPI раздаёт только отдельно перечисленные публичные файлы; служебные пути `/backend/` и `/tests/` закрыты.
5. Проверьте, что во вкладке «Подбор автомобиля» отображаются марки, а не ошибка API, и выполните тестовую заявку с разрешёнными тестовыми данными до включения продакшен-потока.

**Важно:** `index.html` содержит `<meta name="robots" content="noindex,nofollow">` из оригинальной предварительной версии. После принятия юридических документов и полного запуска осознанно измените его на `index,follow`, если нужны поисковая индексация и SEO.

## 4. Как пользоваться админ-панелью

- `#admin` → логин/пароль сотрудника, сессия на 8 часов; токен хранится только в `sessionStorage`, на сервере — лишь его хеш.
- **Заявки:** сотрудники могут принимать, записывать, вести работу, завершать ремонт или подтверждать выдачу; статусы проходят последовательно; дата выполнения и идентификатор сотрудника фиксируются; можно указать дату записи, отменить незавершённую заявку. Для товаров ведутся остатки и резервирование.
- **Отзывы:** после статуса «Работы выполнены» / «Выдан клиенту» сотрудник получает персональную ссылку. Она отправляется клиенту **вручную** через согласованный канал связи. Если ссылка утеряна до отправки отзыва, можно выпустить новую; старая перестанет работать. Один заказ даёт один отзыв. Публикация из админки; сотрудник не может менять текст или оценку автора.
- **Автомобили:** добавление, исправление и скрытие марок, моделей и поколений, а также тип управления, услуги, стоимость, сроки; поле «Данные подтверждены техцентром» открывает показ цен только для подтверждённых позиций. Массовый импорт — CLI ниже.
- **Каталог:** реальный товар и цену добавляет администратор; публикация включается отдельно. Тестовые товары исходного архива не переносятся в живой каталог.
- **Настройки:** контактный телефон и ссылки на VK, Авито, Яндекс Карты и ссылки для дополнительных отзывов. Если точная ссылка на отзывы VK не подтверждена, кнопка не показывается.
- **История изменений:** сервер фиксирует изменение статусов, ревью и администраторские правки.

Все административные API защищены авторизацией и ролями `owner`, `admin`, `staff`. Первую учётную запись создайте CLI. Дополнительные создаются CLI на сервере: замените `--role owner` на `--role admin` или `--role staff`; команда не выдаёт административные права через браузер.

## 5. Импорт данных по автомобилям

В базе предварительно создано 54 производителя, список реальных моделей и небольшое количество поколений **без опубликованных цен и без подтверждения доступности ремонта**. Это расширяемый стартовый справочник, а не полный каталог всех комплектаций. Для машин без точной модификации пользователь может отправить запрос специалисту.

Для массового дополнения подготовьте CSV с заголовками:

```csv
brand,model,generation,year_from,year_to,steering_type,services,price_min,price_max,timeframe,description,confirmed,visible
Ford,Focus,II,2004,2011,ГУР,"Диагностика, ремонт",,,По согласованию,,0,1
```

Сначала проверить без записи:

```bash
python -m backend.import_vehicles vehicles.csv --dry-run
```

Затем импортировать:

```bash
python -m backend.import_vehicles vehicles.csv
```

Для изменения существующих поколений только после проверки исходных данных: `--update-existing`. **В примере не указана стоимость, тип рейки не должен автоматически считаться подтверждённым**; фактические механизмы могут отличаться по комплектации. Нельзя без проверки публиковать чужой прайс или отмечать любую модель как обслуживаемую.

## 6. Юридические и технические ограничения до публичного запуска

1. **Политика персональных данных и согласие в ZIP являются черновиками.** Необходимо внести юридически точные реквизиты оператора, сроки, правовые основания и порядок отзыва, проверить соответствие применимым правилам и опубликовать утверждённые редакции до сбора настоящих данных. Договор-оферта в оригинале также отмечен как проект.
2. Отправки SMS и email не добавлены: нет подтверждённых каналов и ключей. Администратор вручную передаёт ссылку отзыва только завершённому клиенту.
3. Цены по автомобилям пустые, пока сотрудник не подтверждает прайс. Механизм рейки по поколениям может различаться; окончательная цена только после диагностики.
4. Открытая регистрация сотрудников отсутствует намеренно. Если необходимо развернуть публичный API, настройте HTTPS, WAF/ограничение частоты запросов на reverse proxy, мониторинг, резервные копии БД и доступ к файлам только от сервисного аккаунта.
5. Встроенный лимит частоты запросов защищает один процесс API на базовом уровне; для многопроцессного развёртывания добавьте общий rate limiting на прокси. Сессии серверного пользователя хешируются, пароли хранятся через PBKDF2-HMAC-SHA256 с солью.
6. При размещении frontend на GitHub Pages отдельно от API у браузера может быть ограничена работа междоменных запросов; нужен точный HTTPS-адрес API и корректный CORS.
7. Для полноценного эксплуатационного учёта и юридических требований могут потребоваться дополнительные CRM-данные, интеграции SMS, архивирование заказ-нарядов, складские документы и согласованная схема ролей. Здесь реализованы основные сценарии техзадания, но не заявлены отсутствующие интеграции.
